## 4. torch.compile — 結論: まだ使えない

本番の `.venv` は触らず、別に `.venv-compile`（torch 2.7.1+cu126, transformers 5.17）を作った。driver 535 / CUDA 12.2 でも動作する。
`scripts/bench_compile.sh`、`configs/training/bench/` で、実データを使って25 stepずつ計測した。

| 設定 | tok/s（2GPU合計） | mem/GPU | loss（step 25） | 判定 |
|---|---|---|---|---|
| eager（torch 2.7.1） | 38,174 | 36.4 GB | 7.74 | 2.6と同じ |
| layer単位compile | **42,403（+11%）** | 34.3 GB | **10.89（発散）** | grad_normが1.6e7〜7e7。**数値が壊れている** |
| モデル全体compile | - | - | - | 最初のstepで失敗: `CUBLAS_STATUS_EXECUTION_FAILED`（`cublasGemmEx` bf16, 両rank）。全文は `logs/bench-compile-torch27-model.log` |

- layer単位のcompileは速くなるが、学習がまったく進まない（lossが初期値の約10.9のまま）。torch 2.6で出たillegal memory accessと同じ系統の不具合と思われる
- 速くなるのは11%で、30B tokenに換算すると9.1日 → 8.2日。デバッグのコストに見合わないため、**当面はeagerで続け、compileは保留**
- 再挑戦するなら: layer単位compileの壊れ方とモデル全体compileのcuBLASエラーは、どちらもGPUメモリ破壊の系統に見える（torch 2.6のillegal memory accessも同様）。`mode="max-autotune-no-cudagraphs"`、SDPAではなくeager attention、torch 2.8+ を試す
